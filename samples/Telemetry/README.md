# SampleProject — generated protobuf schema

Generated by ProtoDesigner. Regenerate rather than editing by hand.

## This is not the same wire format as the C target

Protobuf is tag-length-value with varints. A message encoded from this schema is a
different sequence of bytes from the same message through the generated C codec, and the
two cannot decode each other. Both describe the same *data*; only one can be on any given
link.

The point of having both is one definition with two consumers: the embedded link keeps the
C codec, while a backend or dashboard speaks protobuf, and nobody maintains a second
hand-written schema that drifts from the first.

Messages using sub-byte fields or quantized values are **not** here — protobuf cannot
represent them, so they were withheld rather than exported as something subtly different.

## protovalidate

Ranges and array capacities are carried as `buf.validate` constraints, which is what
keeps the limits you designed from being lost — protobuf's own types say only
"uint32", not "1000 to 1015". Your build needs to resolve
`buf/validate/validate.proto`, and the consumer needs a protovalidate runtime to
enforce them; they are checked where the message is handled, not on the wire.
